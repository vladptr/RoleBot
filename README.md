# RoleBot

Discord-бот персональных ролей: пользователь нажимает кнопку, получает свою роль, а повторное нажатие открывает **личное** меню — только смена названия и цвета.

## Как это работает

1. Администратор пишет `/setup` в нужном канале — бот публикует панель с кнопкой **Моя роль**.
2. Первое нажатие создаёт роль и выдаёт её пользователю.
3. Второе нажатие показывает сообщение, которое видит только этот пользователь:
   - кнопка **Изменить название** (открывает форму);
   - выпадающий список **цвета**.
4. Другие свойства роли (права, позиция, упоминания) менять нельзя.

У каждого пользователя на сервере может быть только одна такая роль.

## Что нужно заранее

1. Приложение бота на [Discord Developer Portal](https://discord.com/developers/applications).
2. Node.js 18+ (локально) или аккаунт [Render](https://render.com) (хостинг).
3. Git-репозиторий — когда скажешь, куда пушить, подключим remote.

## Настройка бота в Discord

1. Создай приложение → вкладка **Bot** → **Reset Token** и сохрани токен.
2. Включи **Privileged Gateway Intents → SERVER MEMBERS INTENT**.
3. Вкладка **OAuth2 → URL Generator**:
   - scopes: `bot`, `applications.commands`;
   - права: **Manage Roles**, **Send Messages**, **Embed Links**, **View Channels**, **Read Message History**.
4. Открой получившуюся ссылку и пригласи бота на сервер.
5. В настройках сервера подними роль бота **выше** тех ролей, которыми он будет управлять. Без этого Discord не даст создавать и менять роли.

Скопируй **Application ID** со страницы приложения — это `CLIENT_ID`.

## Локальный запуск

```bash
copy .env.example .env
```

Заполни `.env`:

```env
DISCORD_TOKEN=...
CLIENT_ID=...
GUILD_ID=id_сервера
```

`GUILD_ID` нужен, чтобы команда `/setup` появилась сразу. Если его не указать, команда регистрируется глобально и может идти до часа.

```bash
npm install
npm start
```

После запуска в нужном канале выполни `/setup`.

## Чтобы бот не засыпал

На бесплатном хостинге процесс глушат, если на него никто не заходит. Flask-сервер с `Bot is alive!` — как раз для этого: снаружи пингуют URL раз в 5 минут, и инстанс не уходит в сон.

Здесь то же самое на Node: `src/keepAlive.js` поднимает HTTP на `0.0.0.0` и отвечает:

- `/` → `Bot is alive!`
- `/health` → JSON для проверки Render

После деплоя возьми URL вида `https://rolebot.onrender.com` и поставь внешний пинг **каждые 5 минут**:

1. [UptimeRobot](https://uptimerobot.com) → Add New Monitor → HTTP(s) → URL бота, интервал 5 minutes.
2. Или [cron-job.org](https://cron-job.org) с тем же адресом.

Без такого пинга Render всё равно усыпит бесплатный сервис. Сам keep-alive только даёт адрес, который можно дергать; будить его должен уже внешний монитор.

## Деплой на Render

1. Залей проект на GitHub/GitLab (адрес репозитория скажешь отдельно).
2. В Render: **New → Web Service** → этот репозиторий.
3. Настройки:
   - **Runtime:** Node
   - **Build command:** `npm install`
   - **Start command:** `npm start`
   - **Health check path:** `/health`
4. Environment:
   - `DISCORD_TOKEN`
   - `CLIENT_ID`
   - `GUILD_ID` (необязательно, но удобно)
   - `NODE_VERSION` = `20`
   - `DATA_DIR` = `./data`

Привязка «пользователь → роль» хранится в JSON. На Render файлы пропадают при редеплое, если нет диска. Чтобы не терять данные:

1. В сервисе добавь **Persistent Disk**, например путь `/data`.
2. Поставь `DATA_DIR=/data`.

Файл `render.yaml` в корне можно использовать как Blueprint: **New → Blueprint**.

## Переменные окружения

| Переменная | Обязательно | Описание |
|---|---|---|
| `DISCORD_TOKEN` | да | Токен бота |
| `CLIENT_ID` | да | Application ID |
| `GUILD_ID` | нет | ID сервера для быстрой регистрации `/setup` |
| `DATA_DIR` | нет | Папка для `roles.json` (по умолчанию `./data`) |
| `PORT` | нет | Render подставляет сам |

Не коммить файл `.env`.
